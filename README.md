
# Medical Data System

Упрощенная система управления медицинскими данными для университетского проекта.

## Архитектура

### Бэкенд (MedicalDataExchange/)
- **core-service** (REST API Gateway, порт 8099)
- **user-service** (gRPC, порт 50053) - управление пользователями и авторизация
- **data-transfer-service** (gRPC, порт 50052) - медицинские данные и их передача
- **PostgreSQL** (порт 5442)

### Фронтенд
- Современный SPA на vanilla JavaScript
- Без PHP, только HTML/CSS/JS
- Упрощенный дизайн (убраны блокчейн-узлы, сложная аналитика)

## Роли пользователей

### Patient (Пациент)
- Видит только свои медицинские записи
- Может подтверждать/отклонять запросы на передачу данных между клиниками
- Не может создавать/удалять других пользователей

### Employee (Сотрудник клиники)
- Видит пациентов только своей клиники
- Видит медицинские записи своей клиники
- Может создавать пациентов своей клиники
- Может создавать запросы на передачу данных

### Admin (Администратор)
- Видит все данные по всем клиникам
- Полный доступ ко всем операциям
- Может создавать пользователей любых типов

## Запуск проекта

### 1. Запустить бэкенд

```bash
cd MedicalDataExchange
docker compose up -d
```

Проверить что сервисы запущены:
```bash
docker compose ps
```

### 2. Открыть фронтенд

Просто откройте `index.html` в браузере или используйте любой HTTP-сервер:

```bash
# Python
python3 -m http.server 8000

# Node.js
npx http-server -p 8000
```

Затем откройте http://localhost:8000

## API Endpoints

### Авторизация
- `POST /users/login` - вход (email, password)

### Пользователи
- `POST /users` - создать пользователя (публичная регистрация пациента или через токен)
- `GET /users` - список пользователей (требует авторизации)
- `GET /users/{id}` - получить пользователя
- `PATCH /users/{id}` - обновить пользователя
- `DELETE /users/{id}` - удалить пользователя

### Медицинские данные
- `POST /medical-data` - создать запись
- `GET /medical-data` - список (фильтр: user_id, clinic_id)
- `GET /medical-data/{id}` - получить запись
- `DELETE /medical-data/{id}` - удалить запись

### Передача данных
- `POST /transfers` - создать запрос на передачу
- `GET /transfers` - список (фильтр: clinic_id, user_id, status)
- `GET /transfers/{id}` - получить запрос
- `POST /transfers/decision` - решение пациента (подтвердить/отклонить)

## Роутинг

Фронтенд использует hash-based роутинг:

- `#login` - страница входа/регистрации
- `#dashboard` - главная панель (для всех ролей)
- `#patients` - список пациентов (employee, admin)
- `#medical-data` - медицинские записи
- `#transfers` - передача данных

## Логика системы

### Workflow передачи данных:

1. Employee создает запрос на передачу данных между клиниками
2. Запрос получает статус `pending`
3. Patient видит запрос и может:
   - Подтвердить → статус `confirmed`, данные копируются в целевую клинику
   - Отклонить → статус `rejected`

## Безопасность

- JWT токены с ролями (patient/employee/admin)
- RBAC на уровне gRPC interceptors
- Bcrypt для паролей
- Soft delete для пользователей
- CORS настроен (в продакшене указать конкретный домен)

## Разработка

Для разработки фронтенда достаточно запустить HTTP сервер и убедиться что бэкенд на порту 8099 доступен.

Для изменения API URL отредактируйте `assets/js/config.js`:

```javascript
const API_CONFIG = {
    BASE_URL: 'http://localhost:8099',
    // ...
};
```

## Известные ограничения

- Нет валидации форм на фронтенде (минимальная валидация в HTML5)
- Нет пагинации списков
- Нет поиска/фильтрации в UI
- Данные о клиниках хардкодятся (clinic-service не реализован)
- Нет обработки ошибок сети (только базовая)
