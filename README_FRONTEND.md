# 🎨 Фронтенд: Временный доступ к медицинским данным

## 📍 Новая страница

```
http://localhost:8080/patient-access.html
```

## 🎯 Основные возможности

### Для пациентов:
1. **Создать запрос на доступ** к своим медицинским данным
2. **Просмотреть список своих запросов** и их статусы
3. **Получить доступ к данным по токену** (на 15 минут)
4. **Видеть обратный отсчет времени** до истечения доступа

### Для сотрудников клиники:
1. **Просматривать запросы пациентов**
2. **Одобрять или отклонять запросы**
3. **Получать токены доступа** для передачи пациентам

### На фронтенде:
- ✅ JWT токен в localStorage
- ✅ Authorization header для всех запросов
- ✅ Проверка роли пользователя
- ✅ Скрытие недоступных функций

### На бэкенде:
- ✅ Валидация токенов
- ✅ Проверка прав доступа
- ✅ Шифрование данных (AES-256-GCM)
- ✅ Автоматическое удаление через 15 минут

## 🎯 Основные функции JavaScript

### API методы (api.js):
```javascript
// Создать запрос
api.createAccessRequest(patientId, clinicId, medicalDataId)

// Одобрить запрос
api.approveAccessRequest(requestId, approverId)

// Получить данные по токену
api.getTemporaryData(accessToken)

// Список запросов
api.listAccessRequests(filters)

// Отозвать доступ
api.revokeAccess(accessToken)
```

### UI функции (patient-access.html):
```javascript
// Загрузка клиник
loadClinics()

// Загрузка моих запросов
loadMyRequests(patientId)

// Загрузка запросов на одобрение
loadPendingApprovals()

// Одобрение запроса
approveRequest(requestId)

// Просмотр данных
viewMedicalData()

// Обратный отсчет
startCountdown(seconds)
```

## 🐛 Известные ограничения

1. **Mock данные:** Пока API возвращает тестовые данные
2. **Нет real-time:** Списки не обновляются автоматически
3. **Нет уведомлений:** Email/Push уведомления не реализованы
4. **Fabric опционален:** Блокчейн не обязателен для тестирования
