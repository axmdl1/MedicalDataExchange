# 🚀 Быстрый старт - Medical Data Exchange

## ✅ Что уже сделано

### 1. Полноценная структура медицинских данных
- 50+ полей для медицинских записей (витальные показатели, диагнозы, анализы, назначения)
- Реальные клинические данные вместо моков
- Примеры: ОРВИ, гастрит, гипертония, аллергический ринит, травмы

### 2. Временный доступ пациента к данным
- ✅ Пациент создает запрос на просмотр своих данных
- ✅ Клиника одобряет/отклоняет запрос
- ✅ Данные шифруются AES-256-GCM и доступны **ТОЛЬКО 15 минут**
- ✅ Автоматическое удаление после истечения времени
- ✅ Данные хранятся **У КЛИНИКИ**, а не у пациента

### 3. Блокчейн интеграция (Hyperledger Fabric)
- ✅ Smart contracts (chaincode) для управления доступом
- ✅ Immutable audit trail для всех действий
- ✅ Проверка целостности данных (SHA-256 hash)
- ✅ Автоматическое логирование в blockchain

### 4. Автоматическая очистка
- ✅ Scheduler работает каждые 5 минут
- ✅ Удаляет истекшие временные данные
- ✅ Обновляет статусы запросов на 'expired'

## 📋 Тестирование системы

### Сценарий: Пациент запрашивает доступ к своим данным

#### Шаг 1: Создать запрос
```bash
curl -X POST http://localhost:8099/api/patient-access/request \
  -H "Content-Type: application/json" \
  -d '{
    "patient_id": 1,
    "clinic_id": 1,
    "medical_data_id": 1
  }'
```

**Результат:**
```json
{
  "request_id": 1,
  "status": "pending",
  "message": "Запрос на доступ создан. Ожидайте одобрения клиникой."
}
```

#### Шаг 2: Клиника одобряет запрос
```bash
curl -X POST http://localhost:8099/api/patient-access/approve/1 \
  -H "Content-Type: application/json" \
  -d '{"approver_id": 10}'
```

**Результат:**
```json
{
  "request_id": 1,
  "access_token": "a1b2c3d4...",
  "expires_at": "2025-11-19T15:30:00Z",
  "status": "approved",
  "message": "Доступ одобрен. Токен действителен 15 минут."
}
```

**ЧТО ПРОИСХОДИТ:**
1. ✅ Медицинские данные **извлекаются из БД клиники**
2. ✅ Данные **шифруются** AES-256-GCM
3. ✅ Создается **временная копия** (expires_at = NOW() + 15 минут)
4. ✅ Генерируется **уникальный токен доступа**
5. ✅ Запись в **блокчейн** для audit trail
6. ✅ Оригинальные данные **остаются в клинике**

#### Шаг 3: Пациент получает данные
```bash
curl "http://localhost:8099/api/patient-access/data?token=a1b2c3d4..."
```

**Результат:**
```json
{
  "id": 1,
  "visit_date": "2025-11-16T10:00:00Z",
  "department": "General Medicine",
  "attending_doctor": "Dr. Ivan Petrov",
  "chief_complaint": "High fever and severe headache",
  "diagnosis": "Acute upper respiratory tract infection",
  "temperature": 38.7,
  "blood_pressure": "125/78",
  "prescribed_medications": [
    {"name": "Paracetamol", "dosage": "500mg", "frequency": "Every 6 hours"}
  ],
  "lab_results": {"wbc": 8.5, "hemoglobin": 13.2},
  "doctor_notes": "Patient presents with classic viral URTI symptoms..."
}
```

**ЧТО ПРОИСХОДИТ:**
1. ✅ Система проверяет токен
2. ✅ Проверяет срок действия (< 15 минут)
3. ✅ **Расшифровывает** временные данные
4. ✅ Отдает данные пациенту
5. ✅ Записывает доступ в audit log

#### Шаг 4: Автоматическое удаление (через 15 минут)
```bash
# Попытка доступа после истечения
curl "http://localhost:8099/api/patient-access/data?token=a1b2c3d4..."
```

**Результат:**
```json
{
  "error": "access token has expired"
}
```

**ЧТО ПРОИСХОДИТ:**
1. ✅ Система проверяет: `expires_at < NOW()` → **ИСТЕК**
2. ✅ **Немедленно удаляет** временные данные
3. ✅ Обновляет статус запроса на 'expired'
4. ✅ Возвращает ошибку пациенту
5. ✅ **Данные остались в клинике** - ничего не утеряно

### Автоматическая очистка (работает в фоне)

**Scheduler запускается каждые 5 минут:**
```bash
docker logs mde-dt -f | grep cleanup
```

**Вывод:**
```
{"level":"info","message":"Cleanup scheduler started","interval":"5m"}
{"level":"info","deleted_temp_data":5,"updated_requests":5,"message":"cleanup completed"}
```

## 🎨 Схема работы

```
┌─────────────────────────────────────────────────────────┐
│                   CLINIC DATABASE                        │
│  ┌──────────────────────────────────────────────┐       │
│  │   medical_data (ПОСТОЯННОЕ ХРАНЕНИЕ)         │       │
│  │   - Все данные пациента                      │       │
│  │   - Диагнозы, анализы, назначения            │       │
│  │   - НИКОГДА НЕ УДАЛЯЮТСЯ                     │       │
│  └──────────────────────────────────────────────┘       │
│                                                           │
│  ┌──────────────────────────────────────────────┐       │
│  │   temporary_patient_data (ВРЕМЕННО)          │       │
│  │   - Зашифрованная копия данных               │       │
│  │   - expires_at: NOW() + 15 минут             │       │
│  │   - АВТОМАТИЧЕСКИ УДАЛЯЕТСЯ                  │       │
│  └──────────────────────────────────────────────┘       │
└─────────────────────────────────────────────────────────┘

        ▲                                    │
        │ 1. Request                         │ 2. Approve
        │                                    ▼

┌─────────┐                          ┌──────────────┐
│ Patient │  ◄─────────────────────  │    Clinic    │
└─────────┘   3. Access (15 min)     └──────────────┘

        │ 4. After 15 min: AUTO DELETE
        ▼
    ❌ EXPIRED
```
