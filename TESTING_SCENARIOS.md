# 🧪 Сценарии тестирования на фронтенде

## Подготовка к тестированию

### 1. Запустите систему

```bash
cd /Users/damir/clinic-data/MedicalDataExchange

# Запустите бэкенд
docker-compose up -d

# Проверьте что все работает
docker-compose ps

# Должны быть запущены:
# ✓ mde-postgres (5442)
# ✓ mde-user (50053)
# ✓ mde-dt (50052)
# ✓ mde-core (8099)
# ✓ mde-frontend (8080)
```

### 2. Откройте фронтенд

```
Откройте браузер и перейдите на:
http://localhost:8080
```

---

## 📋 СЦЕНАРИЙ 1: Пациент запрашивает доступ к своим данным

### Шаг 1: Войдите как пациент

1. Откройте http://localhost:8080
2. Нажмите "Войти" или перейдите на вкладку Login
3. Введите данные пациента:
   ```
   Email: patient@example.com
   Password: password123
   ```
4. Нажмите "Войти"

**Ожидаемый результат:** Вы вошли в систему как пациент

---

### Шаг 2: Перейдите на страницу временного доступа

1. В адресной строке откройте:
   ```
   http://localhost:8080/patient-access.html
   ```

**Ожидаемый результат:** Открылась страница с 4 вкладками:
- ✅ Создать запрос
- ✅ Мои запросы
- ✅ Ожидают одобрения (для сотрудников)
- ✅ Просмотр данных

---

### Шаг 3: Создайте запрос на доступ

1. Убедитесь что вы на вкладке **"Создать запрос"**
2. В поле "Клиника" выберите любую клинику (например, "Клиника 1")
3. В поле "Медицинская запись" выберите любую запись
4. Нажмите кнопку **"📨 Отправить запрос"**

**Ожидаемый результат:**
- Появилось зеленое сообщение: "✅ Успешно! Запрос на доступ создан"
- Показан ID запроса (например, "#1")

**Что произошло в системе:**
- Запрос сохранен в БД (таблица `patient_access_requests`)
- Статус: `pending`
- Ожидает одобрения от клиники

---

### Шаг 4: Проверьте свои запросы

1. Перейдите на вкладку **"Мои запросы"**
2. Вы должны увидеть список своих запросов

**Ожидаемый результат:**
- Отображается карточка запроса с желтой полоской слева (pending)
- Показан:
  - ID запроса
  - ID клиники
  - ID медицинских данных
  - Дата создания
  - Статус: **"Ожидает"** (желтый бейдж)

### Шаг 4: Одобрите запрос

1. Найдите запрос, созданный в Сценарии 1
2. Нажмите кнопку **"✅ Одобрить"**
3. Подтвердите действие в диалоговом окне

**Ожидаемый результат:**

- Данные зашифрованы (AES-256-GCM)
- Установлен срок действия: +15 минут
- Транзакция записана в блокчейн (если настроен Fabric)

## 👁️ СЦЕНАРИЙ 3: Пациент просматривает данные по токену

### Шаг 1: Выйдите и войдите обратно как пациент

1. Выйдите из аккаунта сотрудника
2. Войдите как пациент (patient@example.com / password123)

---

### Шаг 2: Откройте страницу просмотра данных

1. Перейдите на:
   ```
   http://localhost:8080/patient-access.html
   ```
2. Перейдите на вкладку **"Просмотр данных"**

---

### Шаг 3: Введите токен доступа

1. В поле "Введите токен доступа" вставьте токен, полученный от клиники
   ```
   mock-token-abc123xyz
   ```
2. Нажмите кнопку **"🔍 Просмотреть данные"**

**Ожидаемый результат:**
- Появляется зеленое сообщение: "✅ Данные успешно загружены"
- Отображаются медицинские данные:
  - Диагноз
  - Жалобы
  - Лечение
  - Медикаменты
  - Аллергии
  - Записи врача
  - Результаты анализов
- Запускается обратный отсчет: **15:00** (15 минут)

**Что происходит:**
- Система проверяет валидность токена
- Расшифровывает данные (AES-256-GCM)
- Отображает данные пациенту
- Начинается отсчет времени

---

### Шаг 4: Наблюдайте за обратным отсчетом

1. Смотрите на таймер в красной рамке
2. Он будет отсчитывать время: 14:59, 14:58, 14:57...

**Через 15 минут (или раньше для теста):**
- Таймер достигнет 00:00
- Появится алерт: "⏰ Время доступа истекло! Данные удалены."
- Данные исчезнут с экрана
- В БД запись из `temporary_patient_data` будет удалена

## 🔄 СЦЕНАРИЙ 4: Проверка статуса запросов

### Для пациента

1. Войдите как пациент
2. Откройте http://localhost:8080/patient-access.html
3. Перейдите на вкладку **"Мои запросы"**

**Проверьте статусы:**
- **Желтый бейдж "Ожидает"** = pending (запрос создан, ждет одобрения)
- **Зеленый бейдж "Одобрено"** = approved (доступ предоставлен)
- **Красный бейдж "Отклонено"** = rejected (в доступе отказано)
- **Серый бейдж "Истекло"** = expired (срок доступа истек)

## 📊 СЦЕНАРИЙ 5: Проверка в базе данных

### Проверка созданных запросов

```bash
# Подключитесь к PostgreSQL
docker exec -it mde-postgres psql -U postgres -d medical

# Просмотрите запросы на доступ
SELECT
    id,
    patient_id,
    clinic_id,
    status,
    requested_at,
    expires_at
FROM patient_access_requests
ORDER BY id DESC
LIMIT 5;

# Результат должен показать ваши запросы
```

---

### Проверка временных данных

```sql
-- Просмотрите активные временные токены
SELECT
    id,
    access_token,
    patient_id,
    clinic_id,
    granted_at,
    expires_at,
    expires_at - NOW() as time_left,
    is_revoked
FROM temporary_patient_data
WHERE expires_at > NOW()
ORDER BY id DESC;

-- Результат покажет активные токены и сколько времени осталось
```

---

### Проверка истекших данных

```sql
-- Посмотрите истекшие записи (они должны быть удалены через 5 мин)
SELECT COUNT(*) as expired_count
FROM temporary_patient_data
WHERE expires_at < NOW();

-- Результат должен быть 0 (если cleanup scheduler работает)
```

## 🧪 СЦЕНАРИЙ 6: Тестирование Cleanup Scheduler

### Создайте искусственно истекший токен

```sql
-- Подключитесь к БД
docker exec -it mde-postgres psql -U postgres -d medical

-- Создайте истекший токен
INSERT INTO temporary_patient_data (
    access_token, patient_id, clinic_id, medical_data_id,
    encrypted_data, granted_at, expires_at, is_revoked
) VALUES (
    'test-expired-token-123',
    1, 1, 1,
    'OLD_ENCRYPTED_DATA',
    NOW() - INTERVAL '20 minutes',
    NOW() - INTERVAL '5 minutes',
    false
);

-- Проверьте что создано
SELECT * FROM temporary_patient_data
WHERE access_token = 'test-expired-token-123';
```

---

### Подождите 5 минут

Cleanup scheduler запускается каждые 5 минут и автоматически удалит истекшие записи.

**Или запустите вручную (симуляция):**

```sql
-- Удалите истекшие записи вручную
DELETE FROM temporary_patient_data
WHERE expires_at < NOW() OR is_revoked = true;

-- Проверьте результат
SELECT COUNT(*) FROM temporary_patient_data;
```

**Ожидаемый результат:**
- Истекший токен удален
- Активные токены остались

## 🐛 Возможные проблемы и решения

### Проблема 1: "Token parameter is required"

**Причина:** Не введен токен доступа

**Решение:** Скопируйте токен из алерта после одобрения и вставьте в поле

---

### Проблема 2: "Access token has expired"

**Причина:** Прошло более 15 минут с момента одобрения

**Решение:** Создайте новый запрос на доступ

---

### Проблема 3: Не отображаются запросы

**Причина:** Нет данных в БД или фильтры неверные

**Решение:**
1. Проверьте в БД:
   ```sql
   SELECT * FROM patient_access_requests;
   ```
2. Проверьте консоль браузера (F12) на ошибки

---

### Проблема 4: Таймер не работает

**Причина:** JavaScript ошибка

**Решение:**
1. Откройте консоль браузера (F12)
2. Посмотрите ошибки
3. Обновите страницу (Ctrl+R)

---

### Проблема 5: "Failed to fetch"

**Причина:** Backend не запущен или неверный URL

**Решение:**
1. Проверьте что core-service работает:
   ```bash
   docker logs -f mde-core
   ```
2. Проверьте `assets/js/config.js`:
   ```javascript
   BASE_URL: 'http://localhost:8099'
   ```

## 📝 Заметки

### Время доступа можно изменить

В файле `backend/data-transfer-service/internal/service/patient-access_service.go`:

```go

```

Пока backend возвращает mock данные. Для полной интеграции нужно:

2. Реализовать вызовы к data-transfer-service в handlers
3. Добавить реальное шифрование

Запускается автоматически каждые 5 минут при запуске data-transfer-service.

Проверить логи:
```bash
docker logs -f mde-dt | grep cleanup
```
